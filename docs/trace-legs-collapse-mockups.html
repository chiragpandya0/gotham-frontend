Trace legs — collapsing long stays

A parked vehicle is re-read every few minutes at one camera, so Leg analysis fills with kind: "revisit" rows (0.0 km, no real movement) that bury the legs that matter. Idea: treat a run of consecutive revisit legs at the same camera as one stay, keep every move as its own step, and let the stay expand on demand. A lone revisit (a stay of just 2 reads) is still collapsible, but a camera seen once is never grouped.

A A A B → [A ×3] → B A B B B C D → A → [B ×3] → C → D A B A → A → B → A (return trip is a move, visit 2 — never grouped)

Sample below is plate GJ-03-HR-4679-style data, made up for the mockup: sequence A B B B C D (A = chowk-road, B = hero-showroom, C = ring-road, D = bus-stand). Grouping rule: walk the legs in order; while kind === "revisit" and from_camera_id === to_camera_id equals the open stay's camera, append to it, otherwise close it.

Idea B · Stops timeline instead of a leg table (clearest story)

Idea C · Route breadcrumb that filters the table (best overview + least rework)

Above the unchanged table, a one-line path: A → B ×3 → C → D. Stays show their count. Clicking a pill scopes the table to the legs touching that stop; "all" restores it. Stays are collapsed by default in the table too (as in A), so you get the overview from the pills and the detail from the rows.

Rules I'd apply to any of them

• Group only runs of consecutive revisit legs with the same camera, and only when there are ≥ 1 revisit legs (a stay = 2+ reads at one camera). A→B→A is two moves and stays ungrouped (visit_no > 1 on a move is shown as "back at A", not collapsed).
• Stay summary: camera, read count = revisit legs + 1, dwell = first sighting → last sighting, 0.0 km.
• Selecting a stay row selects its first leg so the map and the detail panel keep working.
• Collapsed by default when a stay has ≥ 2 revisit legs; a single revisit is shown flat.
• Pure frontend: kind, from_camera_id, to_camera_id and visit_no on the legs are all that's needed.
